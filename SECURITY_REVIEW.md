## Исправления

1. Входная защита отбрасывает личку и каналы до обработчиков, регистрации
   пользователей и запросов GitHub. Конфигурация отклоняет положительные id,
   нулевой id и несколько разрешённых групп.
2. Групповой режим закреплён также в роутере, проверке доступа к хакатону,
   личной доставке и `Messenger`. Старые хакатоны лички сохранены в БД, но
   фоновые задания их не обслуживают. Ни общие, ни адресные сообщения не
   отправляются в личку или другую группу.
3. При миграции группа остаётся единственной. Сохранённая цепочка миграций
   применяется при запуске; некорректная цепочка отключает доступ.
4. GitHub-клиент не отправляет Authorization на чужой origin или по HTTP.
   Пагинация не может перейти к другому репозиторию/ресурсу. Отклоняются
   имена репозиториев `.` и `..`. Перенаправления не выполняются.
5. Сервисы назначения, снятия, создания и синхронизации задач проверяют
   разрешённую группу. Старые кнопки и изменение репозитория не дают
   назначить задачу с устаревшими параметрами. Исполнитель должен быть
   зарегистрирован на хакатон и присутствовать в группе.
6. `repr(Settings)` больше не раскрывает Telegram- и GitHub-токены;
   LLM/GigaChat-секреты уже были скрыты. `.env`, БД и логи игнорируются Git
   и не находятся среди отслеживаемых файлов; история пути `.env` пуста.
   Локальному файлу `.env` выставлены права `0600` — чтение и запись только владельцем.

## Логика GitHub и Git

Бот обращается к GitHub через REST API и не запускает shell-команды Git.
В коде нет операций push, merge, удаления веток/репозиториев или изменения
исходников. Разрешённые записи API: создание issue и добавление/удаление
assignees; закрытие, редактирование и удаление issues не реализованы.

Повторное нажатие защищено ревизией личного диалога. Одновременное назначение
одной issue одному человеку дополнительно сериализовано: сохраняется одна
задача и отправляется одно личное уведомление. Если GitHub не назначил assignee,
задача сохраняется в боте с предупреждением. Если не доставлено уведомление,
задача остаётся в `/me → Мои задачи`; публичная замена не отправляется.

GitHub-статусы и уже назначенные задачи по-прежнему синхронизируются;
списки задач изолированы по группе и Telegram user_id. PR нельзя выбрать
вместо issue. Закрытая issue не назначается.

## Сохранённые ограничения

- Привязка GitHub проверяет существование и уникальность логина, но не доказывает
  владение аккаунтом. Это унаследовано от оригинала. В недоверенной команде
  необходима отдельная проверка через OAuth либо подтверждение владельцем бота.
  Текущий режим рассчитан на ранее заявленную доверенную команду «все свои».
- Участники могут изменять хакатоны и назначать задачи другим участникам.
  Это согласованное поведение, а не восстановление административных ограничений
  оригинала. GitHub PAT должен иметь доступ только к предназначенным репозиториям:
  введённый пользователем репозиторий проверяется в пределах прав этого токена.
- Лимиты, проверки публичных URL/DNS/перенаправлений и отдельный процесс разбора
  PDF для импорта сохранены. LLM не получает права выполнять GitHub-операции.
- Реальные назначения GitHub и доставка ephemeral-сообщений в настоящую группу
  в этой проверке не выполнялись. Токен GitHub пока не настроен; chat_id группы
  ещё требуется. Для групповой личной доставки бот должен быть администратором.
