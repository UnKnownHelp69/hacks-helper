# hacks-helper

**Description** a self-hosted Telegram bot that coordinates a small team during hackathons:
deadlines and reminders, participants, GitHub issues as tasks with automatic status
tracking, availability-aware pings, an archive with statistics. Python 3.11+, aiogram 3,
SQLite, long polling. Interface language is Russian. Built to be safe in a public repo:
no secrets in code, works only in explicitly allowed chats, admin rights by Telegram user_id.

---

Telegram-бот для координации команды на хакатонах. Работает в одной общей группе (без топиков),
запускается на домашнем компьютере в режиме long polling (вебхуки и белый IP не нужны).
Бот работает только в одной настроенной группе. Обычные личные чаты полностью отключены.

## Возможности

Создание хакатонов, голосование, выбор команд и редактирование доступны любому
участнику разрешённого чата через `/hack` и кнопки. Админские права пользователю не нужны.

- **Хакатоны**: ручное создание и автоматический импорт из регламентов, три основные даты и чекпоинты, редактирование, несколько хакатонов одновременно.
- **Участники и команды**: самостоятельное голосование, автоматическое создание команды с первым участником, выбор существующей или новой команды. Люди идентифицируются по Telegram user_id.
- **GitHub**: привязка репозитория решения к хакатону. При настроенном токене доступ к новому репозиторию проверяется перед сохранением.
- **Задачи (issue → человек)**: `/hack` → хакатон → «Задачи» → «Назначить issue»: выберите открытую issue и зарегистрированного участника. Исполнитель получает личное уведомление и видит задачу в `/me` → «Мои задачи». Каждые N минут бот обновляет статус: ⚪ не начато, 🟡 в работе (открытый PR со ссылкой на issue или метка `in progress`), ✅ закрыто.
- **Напоминания** перед каждой датой (по умолчанию за 24, 3 и 1 час) с упоминанием участников. Перед пингом бот проверяет, что человек в группе и что ему сейчас можно писать. Напоминания не дублируются после перезапуска и пересчитываются при изменении дат.
- **Доступность**: сохранённые недельные расписания (весь день / окна времени / нельзя) учитываются перед пингами. Если сейчас нельзя, пинг откладывается до ближайшего разрешённого окна, но только если оно наступает до дедлайна.
- **Архив и статистика**: после окончания хакатон уходит в архив. Сохраняются занятое место, закрытые issues (всего и по людям) и число хакатонов у каждого участника.
- **Материалы**: сайт, чат организаторов, ТЗ (ссылкой или файлом).
- **Компактная карточка**: даты, размер команды, число участников и короткие ссылки. Чекпоинты открываются кнопкой под карточкой в том же личном сообщении; при пустом списке кнопка скрыта.
- **Часовой пояс чата**: даты хранятся в UTC, а вводятся и показываются в поясе чата (по умолчанию МСК).

## Команды

В меню и обработчиках оставлены только четыре команды. Они работают в разрешённой
группе, в том числе с суффиксом `@имя_бота`.

| Команда | Что делает сейчас |
|---|---|
| `/help` | краткая справка |
| `/hack` | личное меню: хакатоны, команды, назначение issues и архив |
| `/me` | мои задачи, профиль, привязка GitHub, провайдер и модель нейросети |
| `/github` | привязанный аккаунт GitHub и состояние интеграции |

Старые команды больше не обрабатываются. Все действия с хакатонами доступны через
одно меню `/hack`; `/help`, `/me` и `/github` остаются основными разделами.

### Создание и участие

- **Вручную:** `/hack` → «Создать вручную». Последовательно задайте название, конец
  регистрации, начало, конец и максимум команды.
  После последнего обязательного поля хакатон создаётся и голосование открывается сразу.
  Сайт, репозиторий решения, чат организаторов, ТЗ и до 20 чекпоинтов можно добавить
  в настройках уже созданного хакатона; каждое изменение сохраняется сразу.
- **Автоматически из поста, сайта или документа:** отправьте сообщение в группу;
  отдельной кнопки импорта нет. Пришлите сайт хакатона либо прямую ссылку на положение /
  регламент. Сайт используется для поиска документов: бот проходит ссылки «Положение»,
  «Регламент», «Правила», разделы документов и ссылки скачивания в просмотрщиках.
  Даты, требования к команде и остальные сведения извлекаются только из найденных
  правил (PDF или HTML); рекламные страницы и посты с URL не дополняют эти данные.
  При настроенном OpenRouter или GigaChat документы обрабатывает LLM, затем повторно
  проверяет даты с цитатами. Когда обязательные данные найдены и прошли проверку,
  хакатон создаётся и голосование открывается автоматически. Если данных не хватает
  или они противоречивы, бот пишет «Хакатон не создан» и объясняет причину.
  Частичные результаты импорта не сохраняются. Текстовый пост без ссылки тоже должен
  содержать все обязательные поля. Повторная отправка источника не создаёт второй хакатон.
- **Голосование:** после создания в общий чат приходит карточка с кнопкой «Открыть».
  В личной карточке доступно только следующее действие: «Участвую» для незаписанных
  или «Отмена регистрации» для участников. Команда создаётся с первым
  участником, и бот сообщает об этом в общий чат.
- **Выбор команды:** участники автоматически распределяются по командам до максимума.
  Когда свободных мест нет, участник без команды может создать новую или вступить
  в существующую сверх лимита. Одобрение администратора не требуется. У человека,
  который уже в команде, кнопки создания команды нет. Смена голоса снимает человека
  с команды. Раздел «Команды» сразу показывает составы с Telegram-алиасами; большие
  списки листаются в том же сообщении.
- **Редактирование:** участники чата могут менять данные карточки. Одновременные
  изменения защищены проверкой версии; повторные нажатия не дублируют хакатоны,
  голоса и создание команды. Составы доступны в разделе «Команды».
- **Оповещения:** конец регистрации, начало, конец, чекпоинты и напоминания перед
  ними. Личные расписания учитываются перед пингами. Общие карточки обновляются;
  сбои доставки оставляют уведомления на повторную отправку.

Команды участников формируются **внутри бота**. Регистрацию на сайте организатора
участники проходят по ссылке хакатона.

### Назначение GitHub issues

1. Добавьте репозиторий решения в настройках хакатона.
2. Откройте `/hack` → хакатон → «Задачи» → «Назначить issue».
3. Выберите открытую issue, затем исполнителя из зарегистрированных участников.

Назначать можно без прав администратора. Исполнителю приходит личное уведомление
в текущем чате; задачи со ссылками и статусами доступны ему через `/me` → «Мои задачи».
Если Telegram не доставил уведомление, задача сохраняется, а назначивший видит предупреждение.
Повторное нажатие не создаёт ещё одну задачу или уведомление.

Для назначения на самом GitHub исполнитель указывает свой логин через `/me` →
«Аккаунт GitHub». Без привязки задача назначается в боте, о чём показывается предупреждение.
Токен владельца бота должен иметь доступ к репозиторию и `Issues: Read and write`;
исполнитель — возможность быть assignee в этом репозитории.
Без `GITHUB_TOKEN` сохранённые задачи видны, но выбор и назначение новых issues недоступны.

### Личные сообщения прямо в группе

Используется нативный Telegram Bot API: `BotCommand.is_ephemeral`,
`EphemeralMessageParameters` и `editEphemeralMessageText`. Личные меню, формы,
проверка импорта и результаты действий видны только вызвавшему их пользователю.
Карточки, голосования, составы и оповещения — общие. Открывать личку с ботом не нужно.

Для свободной отправки личных сообщений и автоматического чтения постов бот должен
быть администратором группы; дополнительных прав пользователя не требуется.
Отвечайте на личные запросы ввода, а не отдельным публичным сообщением.

Ephemeral-сообщения могут исчезнуть после перезапуска клиента, а Telegram не гарантирует
их доставку офлайн. Каждая команда `/help`, `/hack`, `/me` или `/github` отправляет
новую личную карточку именно её автору. Кнопка редактирует ту личную карточку, в которой
нажата, даже если после неё участник уже открыл другую панель. Кнопка общей карточки
показывает личный интерфейс на её месте; для остальных участников общая карточка не меняется.
Пошаговый ввод, ход импорта и результат продолжаются в выбранной личной панели.
Возраст карточки сам по себе её не заменяет.
Если Telegram больше не позволяет редактировать карточку, создаётся новая личная карточка.
В группе текст для формы нужно отправлять ответом на личную карточку; обычное публичное
сообщение не используется как ввод формы. Общие карточки голосования и оповещения видны
всем участникам. В обычной личке бот не отвечает ни на команды, ни на кнопки.
Черновиков и восстановления незавершённого ввода нет. При запуске старые незавершённые
формы удаляются; созданные хакатоны, голоса и настройки сохраняются.
При ошибке личной доставки бот не заменяет её публичным сообщением.
[Описание Telegram](https://core.telegram.org/bots/api#ephemeral-messages-and-commands).

## Модель безопасности

Код публичный, поэтому кто угодно может найти бота и добавить его в свою группу. Защита
состоит из нескольких независимых уровней.

**Уровень 1. Одна разрешённая группа.**
- `ALLOWED_CHAT_IDS` принимает ровно один отрицательный id группы или супергруппы.
  Несколько id и положительные id личных чатов отклоняются при загрузке настройки.
- Бот игнорирует все сообщения, команды, изменения сообщений и кнопки в личке,
  включая `/me`. Каналы и inline-кнопки без группового сообщения также отключены.
- Из чужой группы бот выходит без ответа. Если группа не настроена, бот не обрабатывает
  команды нигде, не отправляет уведомления и не выбирает группу автоматически.
- Личные меню и уведомления отправляются адресно внутри группы через native ephemeral API.
  При ошибке доставки публичной замены нет. Команды публикуются только в меню этой группы.
- При миграции в супергруппу старый id заменяется новым; одновременно разрешён только один.
- После добавления в свою группу можно выключить *Allow Groups* в @BotFather.

**Уровень 2. Администраторы бота по user_id.**
- Админы бота перечислены в `BOT_ADMIN_IDS`. Права администратора группы в Telegram на права в боте не влияют.
- Админская команда выполняется, только если чат разрешён и `from_user.id` есть в `BOT_ADMIN_IDS`.
- Сообщения от имени группы или канала админскими не считаются. Команды от их имени бот не выполняет вовсе.

**Уровень 3. GitHub.**
- Fine-grained токен с доступом только к выбранным репозиториям и минимальными правами (см. ниже).
- В коде есть ровно две операции записи в GitHub: создание issue и изменение assignees. Закрывать, редактировать и удалять issues, репозитории или ветки бот не умеет.
- Назначение, создание, снятие и синхронизация задач разрешены только для подключённой группы.
- Пагинация ограничена HTTPS origin GitHub API и исходным ресурсом. HTTP-редиректы
  не выполняются: токен не отправляется на другой сервер.
- В текущем интерфейсе участники назначают задачи другим участникам без прав администратора,
  как предусмотрено правилами команды. Привязка логина не подтверждает владение GitHub:
  указывайте только собственный аккаунт. См. [отчёт проверки](SECURITY_REVIEW.md).

**Прочее:** секреты задаются только через `.env` (он в `.gitignore`), токены вырезаются из логов,
SQL-запросы параметризованы, пользовательский ввод экранируется в HTML.

## Установка и настройка

### 1. Бот в @BotFather

1. `/newbot` → имя и username → получите **токен** (`BOT_TOKEN`).
2. *Bot Settings → Allow Groups?* должно быть **включено**, пока вы добавляете бота в группу. Выключите после добавления.
3. *Privacy mode* можно не трогать. Бот будет администратором группы, а администраторы получают все сообщения группы независимо от privacy mode. Бот видит авторов сообщений и быстрее узнаёт user_id участников. Если вы всё же меняете privacy mode, удалите бота из группы и добавьте заново: изменение применяется только при повторном добавлении.

### 2. GitHub-токен (fine-grained PAT)

GitHub → *Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token*:

- **Resource owner**: ваш аккаунт или организация, которой принадлежат репозитории хакатонов.
- **Expiration**: когда срок истечёт, бот напишет в лог и в ответ на команды «GitHub отклонил токен».
- **Repository access**: *Only select repositories*, выберите репозитории хакатонов.
- **Permissions → Repository permissions**:
  - **Metadata: Read-only**: обязательно, выставляется автоматически;
  - **Issues: Read and write**: просмотр, создание issues, изменение assignees;
  - **Pull requests: Read-only**: определение статуса «в работе» по связанному PR.

**Новый хакатон, новый репозиторий:** откройте токен → *Edit* → *Repository access* → добавьте
репозиторий → *Update*. Бота перезапускать не нужно. После этого токен сможет обращаться к новому репозиторию.

**Репозиторий в организации:** владелец организации должен разрешить fine-grained токены
(*Organization settings → Personal access tokens → Settings*). Если включено одобрение, токен
останется в статусе *pending*, пока владелец не одобрит его в *Personal access tokens → Pending
requests*. Пока токен не одобрен, приватные репозитории организации ему недоступны. При
добавлении новых репозиториев организации может понадобиться повторное одобрение.

### 3. Ваш user_id и chat_id группы

1. Укажите отрицательный chat_id единственной группы в `ALLOWED_CHAT_IDS`.
2. Если id неизвестен, запустите бота с пустой настройкой и добавьте его в нужную группу:
   событие добавления запишет id в локальный лог; команд бот пока не выполняет.
3. Запишите этот id в `.env` и перезапустите. Участники узнают свой user_id через `/me`
   уже внутри разрешённой группы. `BOT_ADMIN_IDS` заполняется при необходимости.

### 4. Файл `.env`

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN`, `ALLOWED_CHAT_IDS`, `BOT_ADMIN_IDS`, `GITHUB_TOKEN`; остальные
параметры описаны в `.env.example` (интервал опроса GitHub, имя метки «в работе», интервалы
напоминаний, часовой пояс по умолчанию, путь к БД и логам).

### Импорт с помощью LLM: OpenRouter и GigaChat

`/me` → «Модель нейросети» → провайдер → модель. Выбор личный, действует для следующих
импортов пользователя во всех подключённых чатах и сохраняется после перезапуска.
Начатый импорт до конца использует прежнюю модель. «Сбросить на настройку бота» возвращает
настройки из `.env`. Список берётся из API провайдера; у OpenRouter показываются модели
с JSON Schema, бесплатные — первыми. Платные модели помечены 💳 и расходуют баланс API.
GigaChat расходует квоту выбранного тарифа. Ключи общие для установки бота; через Telegram
они не вводятся и в базе выбора моделей не сохраняются.

По умолчанию используется OpenRouter. Чтобы выбрать GigaChat для пользователей без
личной настройки, задайте `LLM_PROVIDER=gigachat`. Для OpenAI-совместимого API остаются
`LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`; специальные параметры OpenRouter ему не передаются.

**OpenRouter**

Создайте [API-ключ OpenRouter](https://openrouter.ai/settings/keys) и сохраните его
локально в `.env`:

```dotenv
LLM_API_KEY=
LLM_PROVIDER=openrouter
LLM_MODEL=openrouter/free
LLM_BASE_URL=https://openrouter.ai/api/v1
```

После заполнения ключа перезапустите бота. Отправьте ссылку на сайт или положение.
Бот находит регламент / положение и передаёт выбранному провайдеру только текст,
метаданные, JSON-LD и ссылки из этих документов. Рекламная страница служит навигацией,
её содержание не отправляется LLM и не заполняет данные хакатона. Из документов извлекаются
название, даты, размеры команд, ссылки на материалы и чекпоинты. Неизвестные значения
остаются пустыми. Создание возможно только с полным набором обязательных данных.

В режиме `openrouter/free` бот получает каталог OpenRouter и выбирает до трёх бесплатных
моделей с JSON Schema и совместимыми настройками рассуждений. OpenRouter автоматически
переключается между ними при ошибке или перегрузке; платные модели в этот список не входят.
Каталог кэшируется на время работы бота. Доступность и лимиты зависят от OpenRouter.
Другую модель можно задать в `LLM_MODEL`;
платные модели расходуют баланс API. Импорт работает до двух минут: личная карточка
показывает текущий этап, прошедшее время и заполняется после чтения каждого источника.
После завершения та же карточка показывает созданный хакатон либо причину отказа.
Дополнительного подтверждения публикации нет.

**GigaChat (Сбер)**

Получите ключ авторизации в [кабинете разработчика GigaChat](https://developers.sber.ru/studio/).
Сохраните его в локальном `.env` как выданную строку Base64, без префикса `Basic`:

```dotenv
GIGACHAT_CREDENTIALS=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_CA_BUNDLE_FILE=
```

Для бизнес-аккаунта укажите соответствующий scope (`GIGACHAT_API_B2B` или
`GIGACHAT_API_CORP`). После настройки ключа перезапустите бота и выберите GigaChat
в меню нейросети. Каталог моделей запрашивается у GigaChat; модели embeddings в меню
не попадают. Бот сам получает OAuth-токен, кэширует его до истечения срока и обновляет
после HTTP 401 один раз. На другие ошибки повторные запросы не расходуются.
Структурированные данные извлекаются через вызов функции GigaChat и проверяются той же
схемой, что у OpenRouter. Данные страниц никогда не выполняются как команды.

Проверка TLS включена всегда. Если системе не хватает доверенных сертификатов Сбера,
сохраните официальный PEM bundle из [инструкции GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates)
и укажите путь в `GIGACHAT_CA_BUNDLE_FILE`. Отключать проверку сертификатов не требуется.

За один импорт бот открывает не более шести страниц и читает не более трёх документов.
Поиск использует фактические ссылки с сайта, включая страницы просмотрщиков с кнопкой
скачивания и встроенные PDF; адреса не угадываются. Политики персональных данных и согласия
не используются как правила хакатона. Поддерживаются HTML до 2 МБ и текстовые PDF до 1 МБ,
первых 20 страниц и 60 000 символов (в контекст одного документа попадает до 30 000 символов).
Загрузка проверяет публичность адресов и перенаправлений. PDF читаются в отдельном процессе
с ограничением времени. Документы с обязательным входом, недоступных серверов или PDF-сканы
без текстового слоя могут потребовать ручного заполнения.

LLM получает найденные документы одним запросом, затем отдельным запросом перепроверяет
даты. Для каждой даты она должна привести цитату из документа; бот проверяет наличие цитаты
и соответствие календарной даты. Типографские тире и склейки слов при извлечении PDF
нормализуются. Для даты без времени используются 00:00 (начало) и 23:59 (дедлайн / конец).
Неподтверждённая дата очищается; неполные или противоречащие даты не проходят создание. Правило «регистрация ≤ начало < конец» продолжает проверяться перед
сохранением хакатона.

Один импорт делает до двух запросов к LLM (кроме одного обновления OAuth при 401 у GigaChat),
без повторов при ошибке провайдера. Общий срок поиска, извлечения и перепроверки — две минуты;
одновременно выполняются до двух запросов. При ошибке или таймауте уже найденные данные
не превращаются в сохранённый черновик. Бот создаёт хакатон только при полном наборе
проверенных обязательных полей; иначе показывает причину отказа. Без ключа документы читает
обычный парсер.

Выбор моделей хранится в отдельной таблице схемы 4; обновление сохраняет хакатоны,
голоса, команды и личные настройки. Перед обновлением рабочей установки сделайте SQLite backup
базы. Для возврата на прежнюю версию восстановите этот backup; новые личные настройки
моделей при этом не сохранятся. Если после обновления появились новые хакатоны, вместо
восстановления старой базы можно на остановленном боте удалить только таблицу
`llm_preferences` и вернуть `schema_version` в 3 — данные хакатонов останутся на месте.

При выборе бесплатных моделей бот предпочитает те, у которых рассуждения можно отключить.
Если доступны только модели с обязательными рассуждениями, используется минимальный объём;
для явно указанной модели также задаётся минимальный объём. Лимит ответа — 8000 токенов,
включая рассуждения и JSON. Провайдер выбирается по задержке.
При превышении двух минут бот явно сообщает о таймауте. Обычный парсер также
понимает периоды вида «с 23 октября по 30 октября 2026 года» и использует единственный
явно заданный год периода для дат регистрации без повторения года.

Используется [структурированный вывод OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs)
с дополнительной проверкой типов, дат и ссылок на стороне бота.

## Запуск

### Проверка в одной группе

Укажите один отрицательный id группы в `ALLOWED_CHAT_IDS`, добавьте туда бота
и назначьте его администратором с минимальными правами. Все четыре команды
и личные формы доступны внутри этой группы; обычная личка остаётся отключена.
Пустая настройка отключает все команды и фоновые уведомления.
`/github` показывает состояние интеграции даже без `GITHUB_TOKEN`.

### Docker

```bash
docker compose up -d --build     # запуск (restart: unless-stopped — поднимется после перезагрузки)
docker compose logs -f           # логи
```

БД и файловые логи лежат в именованных томах `bot-data` и `bot-logs`. Чтобы контейнер
поднимался после перезагрузки компьютера, должен автоматически стартовать Docker
(Docker Desktop: *Start Docker Desktop when you sign in*).

Бэкап БД:

```bash
docker compose exec bot python scripts/backup_db.py /app/data/backup.db
docker compose cp bot:/app/data/backup.db ./backup.db
```

### Без Docker (Linux)

```bash
git clone https://github.com/<you>/hacks-helper.git /opt/hacks-helper
cd /opt/hacks-helper
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env
venv/bin/python main.py          # проверка в консоли, Ctrl+C для выхода
```

Автозапуск через systemd (файл `deploy/systemd/hacks-helper.service`):

```bash
sudo useradd --system --home /opt/hacks-helper hacksbot
sudo mkdir -p /opt/hacks-helper/data /opt/hacks-helper/logs
sudo chown -R hacksbot:hacksbot /opt/hacks-helper/data /opt/hacks-helper/logs
sudo chown hacksbot /opt/hacks-helper/.env && sudo chmod 600 /opt/hacks-helper/.env
sudo cp deploy/systemd/hacks-helper.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hacks-helper
journalctl -u hacks-helper -f
```

### Без Docker (Windows)

```powershell
git clone https://github.com/<you>/hacks-helper.git C:\hacks-helper
cd C:\hacks-helper
py -3.12 -m venv venv
venv\Scripts\pip install -r requirements.txt
copy .env.example .env   # и заполните .env
venv\Scripts\python main.py
```

Автозапуск, вариант A — **Планировщик заданий** (*Создать задачу…*):
- *Общие*: «Выполнять вне зависимости от регистрации пользователя» (права администратора не нужны);
- *Триггеры*: «При запуске»;
- *Действия*: запуск программы `C:\hacks-helper\deploy\windows\run_bot.bat`;
- *Параметры*: включите «При сбое выполнения перезапускать через 1 мин» и снимите
  «Останавливать задачу, выполняемую дольше…».

Автозапуск, вариант B — **NSSM** (бот как служба Windows):


### База данных и бэкап

- БД — один файл SQLite: `data/bot.db` (путь задаёт `DATABASE_PATH`), рядом файлы `-wal`/`-shm`.
- Бэкап на работающем боте (консистентная копия через SQLite backup API):
  `venv/bin/python scripts/backup_db.py` → `data/backups/bot-ДАТА.db`. Можно повесить на cron /
  Планировщик. Восстановление: остановить бота, заменить `data/bot.db` копией, запустить.
- Схема БД версионируется: при старте бот сам применяет новые миграции.

## Первые шаги в группе

1. Сделайте бота **администратором без прав**: *Настройки группы → Администраторы → Добавить
   администратора* → выберите бота → **выключите все переключатели** → Сохранить. Бот при
   старте проверяет свой статус: если он не админ, напишет об этом в чат и в лог; лишние
   права перечислит в логе.
2. Выключите *Allow Groups* в @BotFather (см. выше).
3. Каждый участник пишет `/me` — бот запоминает его user_id.
4. `/help` показывает четыре основные команды, `/hack` открывает личное интерактивное меню
   прямо в группе, `/github` — состояние аккаунта и интеграции.
5. Часовой пояс по умолчанию задаётся через `DEFAULT_TIMEZONE` в `.env`.

Если группа превратится в супергруппу, бот сам перенесёт данные на новый chat_id, продолжит
работать и запишет новый id в локальный лог. Замените id в `ALLOWED_CHAT_IDS`.

## Обновление

Перед обновлением работающего бота сделайте резервную копию через
`scripts/backup_db.py`. Схема v3 добавляет таблицы личных диалогов, голосов, команд,
чекпоинтов и уведомлений, сохраняя существующие хакатоны и участников.
Для отката остановите бота, восстановите копию БД и верните предыдущий коммит;
предыдущая версия приложения не открывает БД более новой схемы.

```bash
cd /opt/hacks-helper
venv/bin/python scripts/backup_db.py
git pull
venv/bin/pip install -r requirements.txt
sudo systemctl restart hacks-helper
```

Docker: `git pull && docker compose up -d --build`.

## Код

Структура: 
- `bot/handlers/` — команды;
- `bot/middlewares/` — разрешённые чаты, проверка админа, реестр пользователей;
- `bot/services/` — GitHub, напоминания, доступность, пользователи, синхронизация задач, архив;
-  `bot/db/` — SQLite и миграции, `bot/config.py`, `main.py`;
-  CI (GitHub Actions) запускает ruff и pytest на Python 3.11–3.13.
