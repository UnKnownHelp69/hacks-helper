# hacks-helper

**English:** a self-hosted Telegram bot that coordinates a small team during hackathons:
deadlines and reminders, participants, GitHub issues as tasks with automatic status
tracking, availability-aware pings, an archive with statistics. Python 3.11+, aiogram 3,
SQLite, long polling. Interface language is Russian. Built to be safe in a public repo:
no secrets in code, works only in explicitly allowed chats, admin rights by Telegram user_id.

---

Telegram-бот для координации команды на хакатонах. Работает в одной общей группе (без топиков),
запускается на домашнем компьютере в режиме long polling (вебхуки и белый IP не нужны).

## Возможности

- **Хакатоны**: три даты (конец регистрации, начало, конец), изменение и удаление, несколько хакатонов одновременно. Каждый хакатон имеет короткое имя (`hackaton2026`).
- **Участники**: добавление любым способом указания пользователя, хранение только по Telegram user_id.
- **GitHub**: репозиторий у каждого хакатона, просмотр открытых issues с фильтрами и постраничным выводом, создание issue из Telegram.
- **Задачи (issue → человек)**: назначение через бота или через assignee в GitHub. Каждые N минут бот проверяет GitHub и обновляет статус: ⚪ не начато, 🟡 в работе (есть открытый PR со ссылкой на issue или метка `in progress`), ✅ закрыто. О смене статуса бот пишет в чат.
- **Напоминания** перед каждой датой (по умолчанию за 24, 3 и 1 час) с упоминанием участников. Перед пингом бот проверяет, что человек в группе и что ему сейчас можно писать. Напоминания не дублируются после перезапуска и пересчитываются при изменении дат.
- **Доступность**: у каждого своё недельное расписание (весь день / окна времени / нельзя), включая окна через полночь. Если сейчас нельзя, пинг откладывается до ближайшего разрешённого окна, но только если оно наступает до дедлайна.
- **Архив и статистика**: после окончания хакатон уходит в архив. Сохраняются занятое место, закрытые issues (всего и по людям) и число хакатонов у каждого участника.
- **Материалы**: сайт, чат организаторов, ТЗ (ссылкой или файлом).
- **Часовой пояс чата**: даты хранятся в UTC, а вводятся и показываются в поясе чата (по умолчанию МСК).

## Команды

🔒 — только для администраторов бота (`BOT_ADMIN_IDS`). `<хак>` — короткое имя хакатона.
Команды работают и в формате `/cmd@имя_бота`. Подробная справка с примерами: `/help`.

| Команда | Что делает |
|---|---|
| `/help` | справка с примерами |
| `/me` | зарегистрироваться; показать свой user_id, username, GitHub |
| `/whoami` | **только в личке с ботом**: ваш user_id (для `BOT_ADMIN_IDS`) |
| `/chatid` | id текущей группы |
| `/hacks` | активные хакатоны с участниками и датами |
| `/hack <хак>` | карточка: даты, репо, участники, ссылки |
| `/left <хак>` | сколько осталось до ближайшей даты и какой это этап |
| `/links <хак>` | сайт, чат организаторов, ТЗ (файл бот пришлёт в чат) |
| `/issues <хак> [@user] [label:метка]` | открытые issues (с пагинацией) |
| `/task <хак> <номер>` | взять issue себе |
| 🔒 `/task <хак> @user <номер>` | назначить другому (или ответом: `/task <хак> <номер>`) |
| `/untask <хак> [@user🔒] <номер>` | снять задачу |
| `/tasks`, `/tasks @user`, `/tasks <хак>`, `/tasks <хак> @user` | задачи: мои, человека, всего хакатона по людям |
| `/issue_new <хак> [@исполнитель] <название>` (описание со второй строки) | создать issue; участник может назначить только себя |
| `/link_github <логин>` / 🔒 `/link_github @user <логин>` | привязать GitHub-логин |
| `/unlink_github` / 🔒 `/unlink_github @user` | отвязать |
| `/avail [@user]` | расписание доступности |
| `/avail_set <дни> <когда> [@user🔒]` | изменить расписание: `/avail_set ср 09:00-21:00`, `/avail_set чт нет`, `/avail_set пн-пт 22:00-02:00` |
| `/avail_reset [@user🔒]` | сбросить на «можно всегда» |
| `/history [<хак>]` | архив завершённых хакатонов |
| `/stats` | сколько хакатонов и закрытых issues у каждого |
| `/tz` | часовой пояс чата и текущее время |
| 🔒 `/hack_new <хак> <рег> <начало> <конец> [название]` | создать: `/hack_new hackaton2026 01.11.2026 23:59 05.11.2026 10:00 07.11.2026 18:00 Название` |
| 🔒 `/hack_date <хак> reg\|start\|end <ДД.ММ.ГГГГ ЧЧ:ММ>` | изменить дату |
| 🔒 `/hack_title <хак> <название>` | изменить название |
| 🔒 `/hack_del <хак>` | удалить (с подтверждением кнопкой) |
| 🔒 `/repo <хак> owner/repo` | привязать репозиторий (проверяется доступ токена) |
| 🔒 `/add <хак> @user1 @user2 …` / `/remove …` | участники (или ответом на сообщение человека) |
| 🔒 `/place <хак> <место\|нет>` | место после завершения |
| 🔒 `/site`, `/orgchat <хак> <ссылка\|->` | сайт и чат организаторов |
| 🔒 `/spec <хак> <ссылка>` или файл с подписью `/spec <хак>` или ответ `/spec <хак>` на файл | ТЗ |
| 🔒 `/set_tz <IANA>` | часовой пояс чата (`Europe/Moscow`, `Asia/Yekaterinburg`, …) |

Даты вводятся в формате `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе чата.

### Как указать человека

1. `@username`. Бот ищет его в своём реестре (без учёта регистра) и перепроверяет через Telegram, что username сейчас принадлежит именно этому человеку.
2. Ответ командой на сообщение человека.
3. Упоминание человека без username, выбранного из списка участников (`text_mention`).
4. `me` / `я`: вы сами.
5. 🔒 Числовой user_id.

Если бот кого-то не знает, пусть этот человек напишет в чат любое сообщение или `/me`.
Везде в базе хранится только user_id, поэтому смена username ничего не ломает. При выводе
бот показывает актуальный username (getChatMember, кэш на 5 минут). Списки (история,
статистика, задачи) никого не пингуют, пингуют только напоминания и уведомления.

## Модель безопасности

Код публичный, поэтому кто угодно может найти бота и добавить его в свою группу. Защита
состоит из нескольких независимых уровней.

**Уровень 1. Разрешённые чаты.**
- Бот работает только в чатах из `ALLOWED_CHAT_IDS`. Middleware отбрасывает апдейты из других чатов до того, как их увидит любой хендлер.
- Если бота добавят в чужой чат, он сразу выходит из него, ничего туда не написав, и пишет об этом в лог.
- В личке выполняется только `/whoami`, и он показывает лишь user_id спрашивающего.
- Если `ALLOWED_CHAT_IDS` пуст, включается **режим первичной настройки**: бот ни из каких чатов не выходит и выполняет только `/chatid` в группе и `/whoami` в личке. После заполнения `ALLOWED_CHAT_IDS` и перезапуска `/chatid` работает только в разрешённых чатах, а из остальных бот выходит.
- **Ручная защита (рекомендуется):** после того как бот добавлен в вашу группу, запретите добавлять его в группы: @BotFather → `/mybots` → бот → *Bot Settings* → *Allow Groups?* → *Turn off*. Бот останется в вашем чате, но добавить его куда-то ещё будет нельзя.

**Уровень 2. Администраторы бота по user_id.**
- Админы бота перечислены в `BOT_ADMIN_IDS`. Права администратора группы в Telegram на права в боте не влияют.
- Админская команда выполняется, только если чат разрешён и `from_user.id` есть в `BOT_ADMIN_IDS`. Проверка сделана в одном месте (middleware) и покрыта тестами.
- Сообщения от имени группы или канала (`sender_chat`, анонимные админы) админскими не считаются. Команды от их имени бот не выполняет вовсе.

**Уровень 3. GitHub.**
- Fine-grained токен с доступом только к выбранным репозиториям и минимальными правами (см. ниже).
- В коде есть ровно две операции записи в GitHub: создание issue и изменение assignees. Закрывать, редактировать и удалять issues, репозитории или ветки бот не умеет.
- Все запросы к GitHub делаются только для хакатонов из разрешённых чатов.

**Прочее:** секреты задаются только через `.env` (он в `.gitignore`), токены вырезаются из логов,
SQL-запросы параметризованы, пользовательский ввод экранируется в HTML.

## Установка и настройка

### 1. Бот в @BotFather

1. `/newbot` → имя и username → получите **токен** (`BOT_TOKEN`). Никому его не показывайте; при утечке сделайте `/revoke`.
2. *Bot Settings → Allow Groups?* должно быть **включено**, пока вы добавляете бота в группу. Выключите после добавления (см. «Модель безопасности»).
3. *Privacy mode* можно не трогать. Бот будет администратором группы, а администраторы получают все сообщения группы независимо от privacy mode. Бот видит авторов сообщений и быстрее узнаёт user_id участников. Если вы всё же меняете privacy mode, удалите бота из группы и добавьте заново: изменение применяется только при повторном добавлении.

### 2. GitHub-токен (fine-grained PAT)

GitHub → *Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token*:

- **Resource owner**: ваш аккаунт или организация, которой принадлежат репозитории хакатонов.
- **Expiration**: 90 дней – 1 год. Поставьте себе напоминание: когда срок истечёт, бот напишет в лог и в ответ на команды «GitHub отклонил токен».
- **Repository access**: *Only select repositories*, выберите репозитории хакатонов.
- **Permissions → Repository permissions**:
  - **Metadata: Read-only** (обязательно, выставляется автоматически);
  - **Issues: Read and write**: просмотр, создание issues, изменение assignees;
  - **Pull requests: Read-only**: определение статуса «в работе» по связанному PR.
  - Больше ничего: никаких *Administration*, *Contents*, *Workflows* и т. п.

**Новый хакатон, новый репозиторий:** откройте токен → *Edit* → *Repository access* → добавьте
репозиторий → *Update*. Значение токена не меняется, бота перезапускать не нужно. Затем в чате:
`/repo <хак> owner/repo`.

**Репозиторий в организации:** владелец организации должен разрешить fine-grained токены
(*Organization settings → Personal access tokens → Settings*). Если включено одобрение, токен
останется в статусе *pending*, пока владелец не одобрит его в *Personal access tokens → Pending
requests*. Пока токен не одобрен, приватные репозитории организации ему недоступны. При
добавлении новых репозиториев организации может понадобиться повторное одобрение.

### 3. Ваш user_id и chat_id группы

1. Запустите бота с пустыми `ALLOWED_CHAT_IDS` и `BOT_ADMIN_IDS`. Это режим настройки (см. «Запуск»).
2. **user_id:** напишите боту в личку `/whoami`. Каждый будущий админ делает то же самое.
3. **chat_id:** добавьте бота в группу и отправьте там `/chatid`. Бот ответит id группы и запишет его в лог (у супергрупп id выглядит как `-100…`).

### 4. Файл `.env`

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN`, `ALLOWED_CHAT_IDS`, `BOT_ADMIN_IDS`, `GITHUB_TOKEN`; остальные
параметры описаны в `.env.example` (интервал опроса GitHub, имя метки «в работе», интервалы
напоминаний, часовой пояс по умолчанию, путь к БД и логам).

## Запуск

### Docker

```bash
docker compose up -d --build     # запуск (restart: unless-stopped — поднимется после перезагрузки)
docker compose logs -f           # логи
```

БД и файловые логи лежат в именованных томах `bot-data` и `bot-logs`. Чтобы контейнер
поднимался после перезагрузки компьютера, должен автоматически стартовать Docker
(Docker Desktop: *Start Docker Desktop when you sign in*).

Бэкап БД:

```bash
docker compose exec bot python scripts/backup_db.py /app/data/backup.db
docker compose cp bot:/app/data/backup.db ./backup.db
```

### Без Docker (Linux)

```bash
git clone https://github.com/<you>/hacks-helper.git /opt/hacks-helper
cd /opt/hacks-helper
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env
venv/bin/python main.py          # проверка в консоли, Ctrl+C для выхода
```

Автозапуск через systemd (файл `deploy/systemd/hacks-helper.service`):

```bash
sudo useradd --system --home /opt/hacks-helper hacksbot
sudo mkdir -p /opt/hacks-helper/data /opt/hacks-helper/logs
sudo chown -R hacksbot:hacksbot /opt/hacks-helper/data /opt/hacks-helper/logs
sudo chown hacksbot /opt/hacks-helper/.env && sudo chmod 600 /opt/hacks-helper/.env
sudo cp deploy/systemd/hacks-helper.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hacks-helper
journalctl -u hacks-helper -f
```

Автозапуск, вариант B — **NSSM** (бот как служба Windows):

### База данных и бэкап

- БД — один файл SQLite: `data/bot.db` (путь задаёт `DATABASE_PATH`), рядом файлы `-wal`/`-shm`.
- Бэкап на работающем боте (консистентная копия через SQLite backup API):
  `venv/bin/python scripts/backup_db.py` → `data/backups/bot-ДАТА.db`. Можно повесить на cron /
  Планировщик. Восстановление: остановить бота, заменить `data/bot.db` копией, запустить.
- Схема БД версионируется: при старте бот сам применяет новые миграции.

## Первые шаги в группе

1. Сделайте бота **администратором без прав**: *Настройки группы → Администраторы → Добавить
   администратора* → выберите бота → **выключите все переключатели** → Сохранить. Бот при
   старте проверяет свой статус: если он не админ, напишет об этом в чат и в лог; лишние
   права перечислит в логе.
2. Выключите *Allow Groups* в @BotFather (см. выше).
3. Каждый участник пишет `/me` — бот запоминает его user_id.
4. Админ: `/set_tz Europe/Moscow` (если нужен не МСК), проверка — `/tz`.
5. Админ: `/hack_new hackaton2026 01.11.2026 23:59 05.11.2026 10:00 07.11.2026 18:00 Название`.
6. Админ: `/repo hackaton2026 owner/repo`, затем `/add hackaton2026 @user1 @user2`.
7. Каждый: `/link_github <логин>` (или админ: `/link_github @user <логин>`).
8. По желанию каждый: `/avail_set …` — когда его можно пинговать.

Если группа превратится в супергруппу, бот сам перенесёт данные на новый chat_id, продолжит
работать и напишет новый id в чат и лог. Замените id в `ALLOWED_CHAT_IDS`.

```bash
git pull

```

## Разработка

```bash
python -m venv venv && venv/bin/pip install -r requirements-dev.txt
venv/bin/ruff check . && venv/bin/ruff format --check .
venv/bin/pytest
```

Структура: `bot/handlers/` — команды, `bot/middlewares/` — разрешённые чаты, проверка админа,
реестр пользователей, `bot/services/` — GitHub, напоминания, доступность, пользователи,
синхронизация задач, архив, `bot/db/` — SQLite и миграции, `bot/config.py`, `main.py`.
CI (GitHub Actions) запускает ruff и pytest на Python 3.11–3.13.

## Ограничения

- Статус «в работе» по PR определяется по ссылке из PR на issue (например, `Fixes #12` в описании PR — событие cross-reference). PR, привязанный к issue только вручную в боковой панели *Development*, через REST API не виден; в этом случае используйте метку `in progress`.
- Опрос GitHub периодический (по умолчанию 10 минут), поэтому уведомления приходят с задержкой.
- Состояние постраничного списка `/issues` хранится в памяти: после перезапуска бота кнопки старого списка не работают, достаточно повторить команду.
- В архиве сохраняются только данные истории: ссылки и ТЗ завершённого хакатона удаляются.
- Окно доступности, переходящее через полночь, относится ко дню, в котором начинается: окно «пт 22:00–02:00» действует и в субботу до 02:00.
